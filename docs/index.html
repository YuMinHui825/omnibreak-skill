01

这不是补全，是一个能闭环的调试器

Agent 写完代码，剩下的事交给它。五步一轮，直到程序真的跑通。

STEP 01

部署 Deploy

编译带 -g 调试符号，--deploy-source 自动 SCP 到远程，启动 gdbserver。SSH、本地、docker:// 三种目标。

STEP 02

打断点 Break

按 file:line 下断点，支持条件断点与读/写/访问监视点。也可以 attach 到已经在跑的服务上。

STEP 03

看现场 Inspect

continue / next / step 一次调用就返回线程、栈帧、变量和源码上下文——不用再单独问一遍。

STEP 04

改代码 Fix

崩溃堆栈、变量值、内存泄漏曲线、CPU 热函数，全部映射回 file:line，Agent 拿着这些精确修源码。

STEP 05

验证 Verify

重新编译部署，用 stats 和 diff 量化修复前后：CPU% 降了多少、RSS 少了多少 MB。然后进入下一轮。

02

它在真实机器上能看见什么

不是模拟，不是猜测。GDB/MI、ftrace、Perfetto 采集到的原始事实。

●

崩溃回溯

每一帧都带 file:line，最多 500 帧。信号、崩溃线程、寄存器一并在内。

crash · coredump
◍

内存泄漏

堆采样追踪增长，风险从 none 一路升到 high。配合 Perfetto heapprofd 看原生堆分配火焰图。

leaks · trace --heap-profile
▲

CPU / GPU 火焰图

100Hz 采样生成火焰图，自动探测 GPU ftrace 事件，输出 Top-10 热点函数。

trace · ui.perfetto.dev
◆

I/O 归因

线程卡在 D 状态时，直接告诉你阻塞在哪个内核函数、读了多少字节、是哪个 inode 在拖。

sched_blocked_reason · block_rq_issue
⌁

Sanitizer

解析 ASan / UBSan / TSan 输出，定位越界、未定义行为、数据竞争到具体行号。

sanitize · --asan / --ubsan / --tsan
▣

事后分析

拿着 core dump 离线定位崩溃点，不需要 daemon、不需要 SSH、不需要重启服务。

coredump --binary --core

04

两条命令装完

目标机装 gdbserver，本机装 CLI。已带预编译 JS，不需要 TypeScript 构建。

▸
目标是 Linux 机器。目标机只需 gdbserver + gdb-multiarch，launch / attach 会自动拉起，不用手动跑。
目标机 · 一次性
$ sudo apt install -y gdbserver gdb-multiarch
本机 · 安装 CLI
$ git clone https://github.com/YuMinHui825/omnibreak-skill.git
$ cd omnibreak-skill
$ npm install --production && npm link
Claude Code · 加为 Skill
$ mkdir -p ~/.claude/skills/omnibreak
$ cp SKILL.md ~/.claude/skills/omnibreak/SKILL.md
# 重启 Claude Code 生效

装完之后，你只需要说一句「这里崩了」，Agent 会自己问齐 IP、二进制路径、构建命令，然后开始循环。
